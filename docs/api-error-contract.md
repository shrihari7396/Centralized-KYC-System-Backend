# Global API Error Contract & Status Code Policy

**Standard**: RFC 7807 (Problem Details for HTTP APIs)  
**Applicability**: All Centralized KYC Platform Microservices & API Gateway  
**Revision**: 1.0 (Production Hardening)  

---

## 1. Overview & Objective

To eliminate inconsistent error handling across microservices (where some endpoints returned raw text, others returned ad-hoc maps, and others threw unhandled 500 HTML whitelabel errors), this standard defines a single, deterministic error contract enforced across all platform APIs.

### Core Invariants:
1. **Machine-Readable & Predictable**: All error responses return content type `application/problem+json` with a consistent JSON schema.
2. **Zero Internal Leakage**: Stack traces, internal file paths, raw SQL exceptions, and database entity names must **never** be exposed in API responses.
3. **Traceability**: Every error response includes a unique `correlationId` (or `traceId`) matching the server logs for diagnostic correlation.
4. **Field-Level Validation Granularity**: Request body validation errors provide a structured array of invalid fields and constraints.

## 2. Standard Problem Details Schema

### Standard JSON Schema
```json
{
  "$schema": "https://json-schema.org/draft/2020-12/schema",
  "title": "ProblemDetails",
  "type": "object",
  "properties": {
    "type": {
      "type": "string",
      "format": "uri",
      "description": "A URI reference identifying the problem type."
    },
    "title": {
      "type": "string",
      "description": "A short, human-readable summary of the problem."
    },
    "status": {
      "type": "integer",
      "description": "The HTTP status code generated by the origin server."
    },
    "detail": {
      "type": "string",
      "description": "A human-readable explanation specific to this occurrence."
    },
    "instance": {
      "type": "string",
      "description": "A URI reference identifying the specific occurrence of the problem."
    },
    "errorCode": {
      "type": "string",
      "description": "Platform-specific machine-readable error code."
    },
    "timestamp": {
      "type": "string",
      "format": "date-time",
      "description": "ISO-8601 UTC timestamp when the error occurred."
    },
    "correlationId": {
      "type": "string",
      "description": "Distributed tracing correlation identifier."
    },
    "invalidParameters": {
      "type": "array",
      "description": "Field-level validation errors (if applicable).",
      "items": {
        "type": "object",
        "properties": {
          "field": { "type": "string" },
          "rejectedValue": { "type": ["string", "number", "null"] },
          "message": { "type": "string" }
        },
        "required": ["field", "message"]
      }
    }
  },
  "required": ["type", "title", "status", "detail", "errorCode", "timestamp", "correlationId"]
}
```

## 3. Standard HTTP Status Code & Error Code Policy

| HTTP Status | Category | Platform Error Code | Description / Usage Policy |
| :--- | :--- | :--- | :--- |
| **400 Bad Request** | Validation Failure | `ERR_VALIDATION_FAILED` | Request DTO failed `@Valid` constraints or malformed JSON payload. |
| **400 Bad Request** | Business Precondition | `ERR_INVALID_STATE` | The operation is invalid for the current state (e.g. KYC already verified). |
| **401 Unauthorized** | Missing Authentication | `ERR_AUTH_REQUIRED` | Missing, expired, or malformed JWT in `Authorization` header. |
| **401 Unauthorized** | Invalid Credentials / OTP | `ERR_INVALID_OTP` | The supplied OTP is incorrect or has expired. |
| **403 Forbidden** | Role Authorization | `ERR_ACCESS_DENIED` | Authenticated user lacks required role (e.g. non-ADMIN attempting bypass). |
| **403 Forbidden** | Tenant Isolation | `ERR_TENANT_MISMATCH` | Bank agent attempting to access data belonging to another bank. |
| **404 Not Found** | Missing Entity | `ERR_ENTITY_NOT_FOUND` | Requested user, bank, consent, or KYC record does not exist. |
| **409 Conflict** | Duplicate Resource | `ERR_DUPLICATE_ENTITY` | Email or phone already registered in the user directory. |
| **410 Gone** | Expired Consent | `ERR_CONSENT_EXPIRED` | The consent window has elapsed; a new consent request must be initiated. |
| **429 Too Many Requests**| Rate Limit / Lockout | `ERR_RATE_LIMITED` | OTP attempt limit reached (locked out) or API rate limit exceeded. |
| **500 Internal Error** | Unhandled Failure | `ERR_INTERNAL_SERVER` | Server-side runtime fault. Details logged securely with correlation ID. |
| **502 Bad Gateway** | Upstream Failure | `ERR_UPSTREAM_FAILURE` | External dependency (Groq, DigiLocker, Feign microservice) unreachable. |
| **503 Unavailable** | Circuit Breaker Open | `ERR_CIRCUIT_OPEN` | Circuit breaker tripped due to excessive downstream failures. |

## 4. Example Payloads

### Example 1: DTO Validation Error (400 Bad Request)
```json
{
  "type": "https://errors.kyc-system.com/validation-failed",
  "title": "Validation Failed",
  "status": 400,
  "detail": "Request payload contains 2 invalid parameter(s)",
  "instance": "/user/register",
  "errorCode": "ERR_VALIDATION_FAILED",
  "timestamp": "2026-11-18T11:45:00.123Z",
  "correlationId": "c9a2f64e-0a56-4dc5-8f65-27a9616e45d8",
  "invalidParameters": [
    {
      "field": "email",
      "rejectedValue": "invalid-email",
      "message": "Must be a well-formed email address"
    },
    {
      "field": "mobileNumber",
      "rejectedValue": null,
      "message": "Mobile number must not be blank"
    }
  ]
}
```

## 5. Reference Implementation Contract (Java)

```java
package org.rbi.common.exception;

import com.fasterxml.jackson.annotation.JsonInclude;
import java.time.Instant;
import java.util.List;
import lombok.Builder;
import lombok.Data;

@Data
@Builder
@JsonInclude(JsonInclude.Include.NON_NULL)
public class ApiErrorResponse {
    private String type;
    private String title;
    private int status;
    private String detail;
    private String instance;
    private String errorCode;
    private Instant timestamp;
    private String correlationId;
    private List<InvalidParameter> invalidParameters;

    @Data
    @Builder
    public static class InvalidParameter {
        private String field;
        private Object rejectedValue;
        private String message;
    }
}
```
